# DKIP — Rigorous test prompts

Every prompt below has a **known correct outcome**, so a wrong answer is
detectable rather than a matter of opinion. Work through the sections in order;
Section C is the one that must never fail.

All corpus content is fictional.

## D. Follow-ups and long conversations

Tests the query rewriter (last 10 user turns) and the rolling summary that takes
over beyond that.

### D.1 Pronoun resolution

Run in one conversation, in order:

1. `What is the maximum winch line pull on the ARV-5?`
2. `And with a snatch block?` → must understand "it" is the winch, doubling the line
3. `What rope does it use?` → 28 mm rope, TM-GEN-220
4. `When should that be discarded?` → the rope discard criterion, not the vehicle

### D.2 Topic switch and return

5. `What torque do the wheel nuts take?` → 620 Nm
6. `Go back to the rope — how often is it inspected?` → every 25 operations or 90 days

### D.3 Long conversation — the summary path

Continue the same conversation to **more than 12 turns** using Section A
prompts, then ask:

13. `What was the very first thing I asked you about?`

Expected: it resolves to the winch line pull from turn 1, even though that turn
has aged out of the 10-turn verbatim window. Confirm in the database:

```sql
SELECT title, summarised_upto, left(summary, 200) FROM chat_sessions
ORDER BY created_at DESC LIMIT 1;
```

`summary` must be non-empty and `summarised_upto` greater than 0.

## G. Generalisation — same intent, many phrasings

No keyword tables remain, so all of these must be understood as the same intent.

**All must produce a report plan:**
- `Generate a report on fleet serviceability`
- `Put together a write-up on how the fleet is doing`
- `I need something I can show the CO about vehicle availability`
- `Draft me a brief on recovery capability`
- `Can you pull together an assessment of our serviceability position?`

**All must be understood as chart edits, with a report open:**
- `Make the bars maroon`
- `Swap that for a donut`
- `The chart would look better in green`
- `Can we lose the graph entirely?`

**All must be answered as questions, not treated as report requests:**
- `Is there a report on hydraulics?` ← contains "report" but is a question
- `What does the manual say about generating pressure?` ← contains "generat…"
- `Tell me about the inspection record` ← contains "record"

## Recording results

For each failure worth reporting, capture:

1. The exact prompt and which login you used
2. What you expected, from the tables above
3. What you got — screenshot the answer **with its citations expanded**
4. For a wrong answer: whether it was *uncited* (grounding failure) or *cited
   but wrong* (retrieval failure) — these have different causes

**Severity order.** Section C failures are release-blocking: a Standard account
seeing a confidential figure is a data leak, not a bug. Section B failures come
next — a confident wrong answer is worse than no answer. Everything else is
quality.
